# WriteLite — первый системный MVP

WriteLite — бесплатный помощник для проверки русского и английского текста в полях ввода Windows.

Этот репозиторий содержит первый технический вертикальный срез:

1. приложение запускается в системном трее;
2. отслеживает активное поле через Windows UI Automation;
3. читает доступный текст через `ValuePattern` или `TextPattern`;
4. не обрабатывает поля паролей;
5. показывает оранжевую плавающую кнопку с числом замечаний;
6. открывает панель замечаний;
7. применяет безопасные правки обратно через `ValuePattern.SetValue`;
8. использует небольшой локальный демонстрационный набор правил без сетевых запросов.

## Требования

- Windows 10 или Windows 11;
- .NET 10 SDK;
- Cursor, Visual Studio или VS Code с расширением C#.

## Запуск

Откройте папку проекта в Cursor и выполните в терминале:

```powershell
dotnet restore
dotnet run --project .\src\WriteLite.App\WriteLite.App.csproj
```

После запуска значок WriteLite появится в системном трее. Откройте Блокнот или другое обычное текстовое поле и начните печатать.

## Диагностика совместимости

Во время работы приложение создаёт файл `logs/compatibility.log` рядом с исполняемым файлом. В журнал попадают только технические события: состояние приложения и монитора, имя и идентификатор процесса, тип UI Automation-контрола, поддержка `ValuePattern`/`TextPattern`, признаки `IsPassword`/`IsEnabled`/`IsOffscreen`, результат чтения или записи, а также тип и HRESULT исключения доступа.

Текст поля, найденные фрагменты, предлагаемые замены, имя UI Automation-элемента и текст исключений в журнал не записываются.

Тестовый текст:

```text
Привет  я хотел узнать когда вы сможете отправить заказ,который я оформил вчера.
Вообщем это это очень длинное предложение которое пока должно показать работу первого локального анализатора.
```

## Что уже работает

- обнаружение фокуса на системном уровне;
- чтение стандартных текстовых полей;
- плавающий индикатор;
- локальные правила для пробелов, повторов и нескольких частых ошибок;
- предупреждение о перегруженном предложении;
- применение одиночной правки или всех безопасных правок;
- исключение полей паролей;
- светлый минималистичный интерфейс с оранжевым акцентом.

## Что пока не является полноценным корректором

Текущий `RuleBasedAnalyzer` нужен для проверки всей системной цепочки. Он не претендует на уровень LanguageTool. Сложная орфография, придаточные конструкции, контекстная пунктуация и стилистика будут отдельным языковым модулем.

## Важное ограничение Windows

UI Automation зависит от того, насколько корректно конкретное приложение предоставляет доступ к своему текстовому полю. `TextPattern` предназначен главным образом для чтения, а запись обычно возможна через `ValuePattern`. Поэтому некоторые многострочные, браузерные или нестандартные редакторы могут читаться, но не позволять прямую замену текста.

Архитектура уже разделена на слои, чтобы позже добавить:

- адаптеры Chromium/Electron;
- Text Services Framework для контекстного ввода;
- отдельный безопасный процесс UI Automation;
- локальную модель;
- полноценную базу словарей и правил;
- персональный словарь SQLite;
- кнопку пера с синонимами и переписыванием.

## Локальный ИИ

По умолчанию включён офлайн-профиль **Lite** (`LocalAiEnabled=true`): пунктуация, регистр, частые орфографические и грамматические правки RU/EN без сети и без Python.

```powershell
# Сборка и тесты
dotnet build .\WriteLite.sln -c Debug
dotnet test  .\WriteLite.sln -c Debug

# Обучение / датасет (только для разработчиков; пользователям Python не нужен)
cd ai
python scripts/smoke_pipeline.py
```

Документация: `docs/ai/` (architecture, model-selection, training, integration, privacy, licenses).

Проверка текста и ИИ-анализ выполняются локально; внешние ИИ-провайдеры не используются.
