# WriteLite

Локальный помощник для работы с русским текстом. Проверяет орфографию,
пунктуацию, грамматику и стиль **на вашем компьютере** — без облака, без
обязательного аккаунта, без отправки текста наружу.

**Сайт:** https://writelite-web.vercel.app

---

Установщик ставит приложение в профиль пользователя
(`%LocalAppData%\Programs\WriteLite`) и **не требует прав администратора**.

> Сборка пока не подписана цифровым сертификатом, поэтому Windows SmartScreen
> может показать предупреждение. Сверьте SHA-256 перед установкой.

### Проверка контрольной суммы

```powershell
Get-FileHash .\WriteLite-Setup-x64-1.0.0.exe -Algorithm SHA256
```

Значение должно совпасть со строкой в `SHA256SUMS.txt`.

## Что внутри

Всё работает офлайн — ничего не докачивается при первом запуске.

| Компонент | Версия |
|---|---|
| Языковая модель | WriteLite-Qwen-0.6B-GEC-1.0.1 (база Qwen2.5-0.5B-Instruct, Apache-2.0) |
| Среда запуска модели | llama.cpp, GGUF, **только CPU** |
| Движок правил | LanguageTool 6.4 (LGPL 2.1+) |
| Орфография | Hunspell, словари ru_RU и en_US |

Языковая модель поднимается локальным сервером на `127.0.0.1:8742` и слушает
только петлевой интерфейс.

## Требования

- Windows 10 или 11, x64
- около 2 ГБ свободного места
- 8 ГБ ОЗУ рекомендуется — модель резервирует до 5 ГБ

## Как это устроено

```
Пользователь печатает
   ↓
быстрый проход:  правила + орфография          (без модели, без LanguageTool, без сети)
   ↓  debounce
оркестрованный проход:
     правила  ∥  орфография  ∥  LanguageTool
        ↓
     лексическое вето + регистровые сигналы    (защищает сленг, обсценную лексику, имена)
        ↓
     слияние  ─ одна карточка на одну правку
        ↓
     стилевой слой                             (только STYLE, никогда не ошибка, ≤3 на 100 слов)
        ↓
     WriteLite-Punctuation-v1 @ 0.996          (только предложение, уступает правилам)
        ↓
     проверенные замечания → UI
```

**WriteAI на этом пути нет.** Генеративная модель вызывается только явным
действием пользователя:

```
выделение → Smart Action → WriteAI → валидация → предпросмотр → Применить / Отменить
```

Автоматическая генеративная правка выключена по умолчанию — это измеренное решение,
а не осторожность: неограниченный Qwen даёт precision 0.822 против 0.946, в 4.3 раза
больше ложных срабатываний и в 9.5 раза большую задержку.

### Компоненты

| Слой | Что это |
|---|---|
| Морфология | `RussianMorphology` — полные наборы чтений, порождённые из парадигм и объединённые с индексом форм (3.09 млн форм) |
| Правила | 106 правил в `resources/rules/ru/` (`ru-1.6.0`): грамматика, пунктуация, орфография — каждое со своими условиями, исключениями, примерами и позитивными/негативными тестами |
| Орфография | индекс форм WriteLite + Hunspell `ru_RU` / `en_US` |
| Внешний движок | LanguageTool 6.4 (LGPL-2.1+), отдельным процессом, включается настройкой |
| Пунктуационная модель | `WriteLite-Punctuation-v1` — rubert-tiny2, int8 ONNX, порог 0.996 (заморожен) |
| Реранкер | `writelight-reranker`, для распознавания real-word ошибок |
| WriteAI | Qwen2.5 через llama.cpp, GGUF, только CPU, `127.0.0.1` |

## Измеренное качество

Замороженный корпус `ru_frozen_v1` — 841 предложение, 5 478 токенов,
sha256 `16adfd7c…`. Корпус не подгонялся под результаты; отчёты лежат в
`benchmarks/results/`.

| Конфигурация | P | R | F1 | final-text | FP/100 | no-change | p50 |
|---|---:|---:|---:|---:|---:|---:|---:|
| Только детерминированная (правила + орфография) | 0.942 | 0.720 | 0.816 | 0.674 | 0.299 | 0.969 | **3.4 ms** |
| Отгрузочная (+ LanguageTool, вето, пунктуационная модель) | 0.943 | 0.759 | **0.841** | 0.696 | 0.299 | 0.969 | 139.3 ms |
| Неограниченный WriteAI, для сравнения | 0.822 | 0.732 | 0.774 | 0.652 | 1.493 | 0.877 | 1435 ms |

**Семантических повреждений: 0** во всех прогонах (410 предложений, текст которых
изменился после применения автоправок).

Слабые категории названы честно, а не спрятаны:

| категория | recall | почему |
|---|---:|---|
| Раскладка (`жди` ← `;lb`) | 1.000 | |
| Имена собственные | 1.000 | |
| Орфография | 0.701 | |
| Пунктуация | 0.636 | корпус содержит всего 30 пунктуационных случаев — читать как направление, не как измерение |
| Морфология | 0.319 | цели — отказы генерации, а не выбора; закрыть их значит сомневаться в 78 % правильных слов |
| Real-word ошибки | 0.062–0.125 | нужен контекстный слой и расширение 405 наборов смешиваемых слов — это работа с данными и отдельной проверкой лицензий |

## Сборка

```powershell
dotnet restore
dotnet build .\WriteLite.sln -c Debug
dotnet test  .\WriteLite.sln -c Debug
dotnet run --project .\src\WriteLite.App\WriteLite.App.csproj
```

> **Важно.** Если WriteLite уже запущен (он сворачивается в трей, а не закрывается),
> сборка `WriteLite.App` упадёт на копировании DLL — процесс держит файлы.
> Завершите его перед сборкой.

Модельные веса (`*.onnx`, `*.gguf`, `*.safetensors`), лексическая база (145 МБ) и
сгенерированные лексические паки **не хранятся в репозитории**. Они пересобираются
скриптами из `ai/scripts/`; хеши и число записей зафиксированы в
`resources/lexical/sources.manifest.json` и проверяются `LexicalProvenanceTests`.

## Воспроизведение измерений

Инструменты в `tools/` **не входят в `WriteLite.sln` целиком** и держат приватные
копии `WriteLite.dll` и пакета правил — `dotnet build WriteLite.sln` их не
пересобирает. Каждое измерение делайте после явной пересборки инструмента,
иначе замеряется код до изменений.

```powershell
dotnet build tools\langbench\langbench.csproj -c Release
tools\langbench\bin\Release\net10.0-windows\langbench.exe --layers rules,spell --label det
tools\langbench\bin\Release\net10.0-windows\langbench.exe --layers rules,spell,lt,lexveto,lexsignals,punct --label shipping
```

Другие пробники: `morphprobe` (морфология), `spellbench`, `punctsafety` (проверка
порога на заведомо правильном тексте), `fieldmatrix` (совместимость внешних полей
через боевой путь записи), `judgebench`, `rerankdiag`.

| WPF `TextBox` | WPF | PASS | PASS | `value-pattern` | 28 |
| WPF `RichTextBox` | WPF | PASS | PASS | `selection-paste` | 241 |

совпадёт с тем, что обещало исправление.

## Известные ограничения

- **Причастные и деепричастные обороты** детерминированно не решены: нужно знать,
  где кончается оборот и есть ли у него зависимые, а это разбор.
- **Пунктуационная модель на техническом тексте и латинице внутри русского**
  деградирует примерно вдвое быстрее, чем на обычной прозе. На пороге 0.996 она там
  ничего не предлагает — слабость латентная, и это причина не доверять её ослаблению.
- **Стиль покрывает то, что решается закрытыми списками.** Плотность пассива и
  неясная референция местоимений отсутствуют намеренно: им нужно понимать смысл.
- **LanguageTool — 602 МБ резидентно** и основной вклад в задержку полного конвейера
  (135 ms против 3.4 ms без него). Его собственная precision на корпусе — 0.41.
- **Старт 5.98 s**, крупнейший вклад — разбор `morphology-index.json` (16 МБ).
- **94 МБ дублирующегося лексического JSON** в поставке: база данных уже содержит
  все 142 853 записи, но каталог паков перечисляет установленные паки чтением
  именно этих файлов.
- **131 warning** в Release-сборке — существующий долг, не блокирует.
- Реальный GUI мышью/клавиатурой автоматически не проверяется.

Подробнее — `FUTURE_WORK.md` и `docs/language-engine-phase7-release-report.md`.

## Приватность

Проверка текста и ИИ-анализ в десктопном приложении выполняются локально, на
вашем устройстве. Внешние ИИ-провайдеры не используются, текст никуда не
отправляется.

Журнал `logs/compatibility.log` содержит только технические события: состояние
приложения, имя и идентификатор процесса, тип UI Automation-контрола, поддержку
паттернов, результат чтения или записи, HRESULT исключения. Текст поля, найденные
фрагменты, предлагаемые замены, имя элемента и текст исключений в журнал **не
пишутся**. Поля паролей исключены из обнаружения и никогда не декорируются.

Веб-редактор на сайте — отдельная история: там текст уходит на сервер WriteLite,
обрабатывается в памяти, не сохраняется и не попадает в журналы. Полные условия —
в [политике конфиденциальности](https://writelite-web.vercel.app/ru/privacy).
