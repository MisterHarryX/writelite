# WriteLite: контрольная точка 2026-08-01

Рабочая ветка: `feat/writelite-ecosystem`. Изменения намеренно не закоммичены и не опубликованы. На контрольной точке solution собирается, автоматические тесты проходят:

```powershell
dotnet test WriteLite.sln -c Release --nologo
```

Результат: 423 успешно, 0 сбоев, 3 пропущено. Пропущены живые интеграционные тесты, которым нужен запущенный локальный Qwen/LanguageTool host. Остаются предупреждения анализатора MSTest, ошибок компиляции нет.

## Что реализовано

- Продукт и локальные анализаторы переведены на русский-only.
- Удалены проект `WriteLite.Cloud`, облачные AI-провайдеры, токены, секреты и пользовательские настройки облака.
- Удалены собственные английские rule-pack/Hunspell и проект английского языка.
- Сохранены только локальные AI-пути: in-process lite rules и loopback Qwen; LanguageTool также ограничен локальным loopback-контуром.
- Расширены русские правила, метаданные rule-pack и регрессионные тесты.
- Русская орфография использует Hunspell и консервативные стабильные исправления; неизвестное слово само по себе не объявляется ошибкой.
- Пользовательский словарь переведён на версионированный русский формат.
- Обновлены локальные лексические пакеты и воспроизводимые Python-сборщики. Полный словарь Ожегова не включён: импорт разрешён только из отдельно лицензированного пакета.
- Реализованы смысловые блоки длинного текста с перекрытием, глобальными UTF-16 смещениями, объединением результатов, отменой, ограничением параллелизма и прогрессом. Есть тесты на 20 000, 50 000 и 100 000 символов.
- Усилены проверки UI Automation, актуальности цели/снимка/диапазона и безопасного применения исправлений.

## Что обязательно проверить перед релизом

Эта контрольная точка не является подписанным production-релизом. Автоматические тесты зелёные, но исходное задание требует ручных и живых проверок, которые здесь не завершены:

1. Запустить приложение и визуально проверить все основные экраны в светлой/тёмной теме, масштабах Windows 100/125/150% и нескольких размерах окна.
2. Пройти UI Automation-матрицу: Блокнот, Word/современный WordPad-аналог, Telegram Desktop, браузерные `textarea`/`contenteditable`, WPF, WinForms, Win32, read-only и password-поля.
3. Запустить живые Qwen и LanguageTool smoke/integration tests; проверить повреждённую/отсутствующую модель, timeout, cancellation и повторный запуск.
4. Проверить сетевой трафик при запуске и анализе. Допустим только loopback для локальных движков; обновления и Telegram-поддержка должны оставаться отдельными подсистемами и не получать пользовательский текст.
5. Выполнить secret scan и проверить состав publish/release-папки: облачные URL, ключи, English assets и удалённый `WriteLite.Cloud` не должны попасть в поставку.
6. Пересчитать SHA-256 всех изменённых лексических артефактов и синхронизировать `resources/lexical/sources.manifest.json`, включая hash `historical-sample.manifest.json`.
7. Обновить и вручную сверить `THIRD_PARTY_NOTICES` с фактически поставляемыми Hunspell, OpenRussian/OpenCorpora/прочими данными и runtime-компонентами.
8. Измерить startup/idle CPU/RAM, время быстрого/глубокого анализа и длинных документов. Метрики «до/после» пока не зафиксированы полностью.
9. Не запускать production-обучение модели до аудита лицензий датасета, разбиения без утечек и baseline-оценки. Текущую модель заменять только при снижении ложных исправлений на тестовом корпусе.

## Рекомендуемый порядок продолжения

```powershell
cd E:\Programming\DProjects\WriteLite-Starter\WriteLite-Starter
git status --short
dotnet test WriteLite.sln -c Release --nologo
git diff --check
```

Затем выполнять пункты ручной проверки выше. После их завершения:

```powershell
dotnet clean WriteLite.sln -c Release
dotnet build WriteLite.sln -c Release --nologo
dotnet test WriteLite.sln -c Release --no-build --nologo
```

Перед коммитом внимательно просмотреть удаления и крупный diff. Не применять `git reset --hard`. Рекомендуется разделить изменения минимум на отдельные коммиты: cloud/English removal, RU rules/spelling, lexical data/licenses, long-text/UIA, tests/docs. Публикацию и создание PR выполнять только после ручной проверки.
